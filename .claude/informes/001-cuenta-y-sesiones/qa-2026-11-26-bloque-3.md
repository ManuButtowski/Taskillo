## Hallazgos
1. **[grave]** `apps/api/src/lib/logger.ts:19` (rama `Error` de `redact`) y `apps/api/src/app.ts:190` (`unhandled_error`). El log escribe `err.message` tal cual y el `DrizzleQueryError` de drizzle 0.45 incluye en el mensaje `Failed query: <SQL>` y `params: <valores>`. Cualquier fallo de base de datos en un manejador deja en el log los parámetros de la consulta: correo, `password_hash`, hashes de refresh y hash del código de registro. Incumple SC-005 y la regla de "nunca un secreto en un log" (el hash del código es `sha256(correo:código)` de 40 bits: reversible por fuerza bruta durante los 30 min de vida).
   - Pasos: con la API en Docker sin migrar, `POST /api/v1/auth/register {"email":"qa1@example.com"}`; `docker logs taskillo-api-1`. Con `new DrizzleQueryError(sql, [email, hash], cause)` pasado a `createLogger().error(...)` sale el hash completo.
   - Esperado: el log lleva solo el nombre del error y, como mucho, el código de PostgreSQL. Obtenido: `"message":"Failed query: select ... params: qa1@example.com,1"`.
   - El test de SC-005 no lo detecta porque solo prueba un error sintético (`/boom`). Falta un test que fuerce un fallo de consulta (por ejemplo cerrar el pool) en login, refresh y paso 2 y compruebe el log. Lo mismo vale para `mail_send_failed` (`mail/background.ts`).
